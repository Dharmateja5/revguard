Architecture

System boundaries, agents, MCP, controls, state, and execution

1. Architectural Principle

Agents investigate. Deterministic systems decide, authorize, and execute.

3. Decision Layers

LayerResponsibilityMust Not Do
JevStructured routing, case classification, path recommendation, fallback signalFinancial authority or execution
Generative agentsHypotheses, evidence discovery, cross-source reasoning, planning, synthesisAuthoritative finance, policy override, direct financial writes
Deterministic controlEvidence verification, sufficiency, finance, policy, authorization, state, execution, auditProbabilistic reasoning

4. Agent Responsibilities

Coordinator

Owns investigation objective, durable state, budgets, agent delegation, evidence gaps, next action, completion and escalation.

Contract & Entitlement Agent

Finds governing contracts, amendments, pricing terms, effective dates, approvals, and entitlement evidence.

Billing Reconciliation Agent

Examines invoices, lines, credits, usage, billing history, telemetry, and discrepancy patterns.

Recovery Recommendation Agent

Combines verified findings into a structured recommendation and evidence package. It cannot execute.

7. Evidence Trust Boundary

Agents propose claims and evidence references. A deterministic verifier re-retrieves the source/version/snapshot and validates the cited span. The system separately checks whether the source is authoritative for the decision.

PROVENANCE: Where did this claim come from?
AUTHORITY:  Is this source allowed to govern this decision?

8. Financial & Policy Boundary

The financial engine uses verified structured inputs only. Example:

leakage_amount = round((contracted_rate - billed_rate) * billable_units, 2)

Policy then checks evidence sufficiency, verified-only inputs, threshold/cap, scenario allowlist, dispute state, unresolved conflict, and authorization requirements.

9. Identity & Authorization

Use least privilege. Read-oriented agents should not hold recovery.execute or policy.override. Execution authority belongs to a deterministic recovery service and is contingent on current investigation state, policy outcome, authorization artifact, and idempotency key.

10. Recovery State Machine

INVESTIGATION → RECOMMENDATION_READY → POLICY_EVALUATED
→ HITL | EXECUTION_PENDING | NO_ACTION
HITL → APPROVED → EXECUTION_PENDING
EXECUTION_PENDING → EXECUTING
EXECUTING → EXECUTED | RETRYABLE_FAILURE | UNKNOWN_EXECUTION
UNKNOWN_EXECUTION → RECONCILIATION
EXECUTED → VERIFICATION_PENDING → VERIFIED

11. P1 Conversational Evidence Path

Recorded Call → ASR + Diarization → Speaker-attributed transcript
→ timestamped EvidenceItem → Verification → Authority Check → existing pipeline

No separate conversation agent is required for MVP. Participant role mapping should come from controlled metadata, not diarization itself.

12. Observability

Trace investigation ID, routing decision, tool calls, retries, model/agent spans, latency, tokens, evidence verification, finance result, policy outcome, termination reason, and execution verification. Keep private reasoning out of logs.
