Supplier Exception Resolution
08 — Architecture Decisions

Architecture Decision Records

ADR-001 — Narrow to Supplier Commitment Exceptions

Decision: P0 supports quantity/date supplier commitment failures only.

Why: preserves a genuinely dynamic investigation loop while keeping the operational simulator manageable.

ADR-002 — One Coordinator, Capability Modules First

Decision: avoid a large agent swarm. Use one coordinator with specialist capabilities; split into independent agents only if evaluation shows value.

ADR-003 — Jev Owns Structured Decisions and Tool Calls

Decision: Nemotron produces reasoning/action intent; Jev maps intent into typed tool calls and structured routing outputs.

ADR-004 — Deterministic Operational Math

Decision: shortage, projected coverage, cost totals, threshold checks, and state transitions are deterministic.

ADR-005 — Agents Cannot Authorize Their Own Writes

Decision: write authorization is owned by deterministic policy and explicit HITL rules.

ADR-006 — Verify Every Write

Decision: every sandbox recovery action is followed by read-back/recalculation before the case can complete.

ADR-007 — Unknown Execution Is a First-Class State

Decision: write timeout after request submission transitions to UNKNOWN_EXECUTION; reconcile before any retry.

ADR-008 — Evaluation Uses Valid-Action Sets

Decision: benchmark cases may have more than one valid recovery path. Evaluation checks feasibility, policy compliance, and resolved outcome rather than forcing one arbitrary “correct” action.

ADR-009 — Synthetic Data Is the Source of Truth

Decision: build scenarios first, then synthetic enterprise data. This avoids market-data quality problems and enables exact ground truth.

ADR-010 — Python 3.12 Baseline

Decision: use Python 3.12 unless a required SDK forces 3.11.
