Evidence & Data

Synthetic data, evidence contracts, source authority, and benchmark design

1. Purpose

Define the synthetic enterprise dataset and evidence contracts used by agents, MCP tools, deterministic controls, and evaluation.

2. Source Domains

DomainExample DataAuthority
ContractMaster contract, amendments, pricing schedules, effective datesAuthoritative for commercial entitlement when executed/current
UsageMetered units, telemetry health, usage summariesAuthoritative for measured usage when source passes health checks
BillingInvoices, lines, credits, billing historyAuthoritative for billed amounts
CRM / ApprovalNotes, approved exceptions, disputes, account metadataApproval system authoritative for commercial exception approval
Conversation (P1)Recorded customer/account-team callsEvidence of what was said; not automatically authoritative for contract change
RecoverySandbox recovery requests and statusesAuthoritative for recovery execution state

3. Core Evidence Schema

{
  evidence_id,
  source_type,
  source_locator,
  source_version,
  snapshot_id,
  retrieved_at,
  extracted_claim,
  citation_span,
  effective_date,
  verification_method,
  verification_status
}

verification_status ∈ {VERIFIED, MISMATCH, UNVERIFIABLE}

4. Case-Level Evidence Status

SUFFICIENT, INSUFFICIENT, CONFLICTING, or UNAVAILABLE.

5. Synthetic Dataset Minimum

AssetMinimum
Customers10–20
Contracts / amendments15–30 mixed valid/expired/conflicting records
Invoices / invoice linesSeveral periods per customer
Usage recordsEnough to support normal, missing, and anomalous scenarios
CRM approvals / disputesApproved, missing, expired, and disputed cases
Ground-truth benchmarkAt least 12–20 cases spanning recovery, no-action, HITL, and failure paths
Recorded calls (P1)1–3 synthetic recordings

6. Recommended Benchmark Mix

  • Incorrect rate
  • Missed usage
  • Expired concession
  • Approved exception
  • Telemetry anomaly
  • Conflicting amendment
  • Open dispute
  • Missing critical evidence
  • Duplicate recovery attempt
  • Unknown execution/reconciliation
  • Voice contradiction (P1)

7. Voice Evidence Representation

{
  call_id: "CALL-0042",
  recording_id: "REC-0042",
  speaker_id: "speaker_1",
  participant_role: "ACCOUNT_MANAGER",
  start_sec: 42.1,
  end_sec: 48.7,
  text: "We'll continue the 15% discount through September..."
}

The participant_role should come from call metadata or controlled synthetic setup. Diarization identifies speaker segments, not real-world identity or authority.
